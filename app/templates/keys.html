Keys and certificates

OIDC signing keys

Authelia signs ID tokens with the first key and publishes all of them, so apps can verify old and new tokens while you rotate. Rotation takes three steps spread over time; each one restarts Authelia and is rolled back automatically if the published keys are not what was expected.

{% if not state.migrated %}

Key rotation is not set up yet. The signing keys are still inside Authelia's main configuration file, which this tool never writes. A one-time move puts the private keys into protected files that Authelia reads through its template filter:

  1. On the host, in the folder with your compose file (adjust the config path and the user to yours): 
    docker run --rm --network none --user 1000:1000 \
  -v "$PWD/data/authelia/config:/config" \
  ghcr.io/shuricksumy/authelia-configurator:authelia-{{ bundled_version }} \
  python -m scripts.migrate_jwks --config /config/configuration.yml --managed /config/managed
    It writes managed/oidc_jwks.yml and the key files into managed/secrets/, changes nothing in the main file and prints what to do next.
  2. Add ,/config/managed/oidc_jwks.yml to Authelia's X_AUTHELIA_CONFIG. The main file's jwks: list can stay: the managed list replaces it (remove it later to tidy up).
  3. Set X_AUTHELIA_CONFIG_FILTERS=template for Authelia and CONFIG_FILTERS=template for the configurator, then restart both.

The full guide is docs/jwks.md.
